  All edits now save to a DRAFT first (requirement: preview before publishing).

BEFORE / AFTER
  before: menu/footer/hero buttons/homepage order were hardcoded in JSX; every
          site text change required an edit + rebuild + redeploy.
  after:  all of it lives in site_settings; edits go to a draft, are previewed
          on the real storefront (admin only), and publish instantly.

RISKS & NOTES
  * Preview merge must stay admin-gated. If a normal visitor ever sees draft
    content, getSettings() authorization is broken — treat as P0.
  * Setting a homepageSections id that isn't in the allowed list is silently
    filtered (defensive) — a typo hides the section, not an error.
  * NAV/FOOTER/HERO defaults are in code (DEFAULT_* in store.ts) and only apply
    when nothing is saved; once the admin saves, the DB wins.
  * The host REWRITES .env on restart -> admin creds moved to .env.local
    (verified surviving a restart). Documented in config.txt.
